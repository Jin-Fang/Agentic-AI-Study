# 第 10 章：知识、幻觉与不确定性

LLM 经常显得知识丰富，因为预训练把大型文本集合中的统计规律编码进了模型参数。这些规律支持回忆、解释和泛化，却不构成权威事实记录。即使语气和格式很像可靠答案，模型仍可能生成错误、过时或缺乏依据的流畅文本。

Karpathy 在 introduction 中把幻觉（hallucination）作为核心失败模式提出：模型没有内置的真理 oracle，却可以生成看似合理的文本（[Intro to LLMs, around 00:10:04](https://www.youtube.com/watch?v=zjkBMFhNj_g&t=604s)）。幻觉并不只发生在完全没有证据时。模型也可能误读已提供的证据、引用其中错误的部分，或把主张延伸到证据支持的范围之外。

## 参数化知识不是数据库

参数化知识（parametric knowledge）是可以从学习到的权重模式中引出的信息。它不像数据库那样保证记录唯一、来源明确或数值最新。某个事实在训练数据中可能以多个相互矛盾的版本出现，也可能因为非常少见而只得到微弱表示，还可能在相关训练数据收集之后发生变化。

这也意味着，“存储”只是一种比喻。通常没有某一个参数或某一行与单个事实对应。相关的名称、日期、措辞和关联分布在整个网络中，并与当前 context 相互作用。同一事实换一种问法，可能在一次 prompt 中成功引出正确关联，在另一次 prompt 中却引出不同或错误的关联。

尽管如此，参数化知识仍然有用。重要的边界在于：来自参数的合理答案是一项预测，不是从权威来源读取的记录。

## 可信假答案如何产生

预训练目标奖励对可能 continuation 的预测，而不是逐项对照现实检查每个主张。训练文本也包含错误、迷思、虚构内容、过时材料，以及没有标注真假的自信陈述。Post-training 可以让答案更有帮助、更完整，但有帮助和完整都不保证事实性。

形如答案的 prompt 还会把可能的 continuation 进一步推向形如答案的回答。如果问题预设了一个不存在的事件、书籍或定理，顺着该前提继续生成，在统计上可能比质疑它更容易。如果在没有来源时要求精确引用，即使组合出来的文献并不存在，标题、作者列表、期刊和年份也都可能各自显得合理。

以下情况的风险尤其高：

- 所需事实非常少见或很新；
- 问题包含强烈但没有依据的前提；
- 没有提供来源，却要求精确引文或引用；
- 交互更奖励流畅完成或权威格式，而不是承认不确定性。

生成的文字可能很像百科条目、法律条款或研究文献。这样的权威外形会提高读者的信心，却不会提高答案的真实性。

## 模型层错误类型

错误或缺乏依据的答案可能来自多种机制：

- **回忆错误（recall error）**替换了错误的名称、日期、关系或细节；
- **知识过时（staleness）**复现曾经为真或曾经常见、但目前已经不再适用的说法；
- **混合拼接（conflation）**把不同人物、文档、事件或概念的属性混在一起；
- **模仿性错误（imitative falsehood）**复现人类文本中的误解和迷思。TruthfulQA 的设计目标正是检验模型能否给出真实答案，而不是模仿看似合理的人类错误（[TruthfulQA](https://arxiv.org/abs/2109.07958)）；
- **错误前提顺从（false-premise compliance）**接受没有依据的前提，并围绕它生成解释。例如，“X 为什么发生？”会把 continuation 引向原因，即使“X 是否发生”本身仍有待确认；
- **证据误用（evidence misuse）**与已提供材料矛盾、选择了错误段落，或推导出材料并不支持的结论。

这些类型会相互重叠，而且并非每个错误答案都能暴露其内部成因。它们仍然有用，因为它们说明，幻觉远不只是从空白 context 中编造事实。

## Grounding 改变的是输入

Grounding 会把外部证据或 observation 放入模型的当前输入。这可以提高生成受支持 continuation 的概率，却不会重写模型参数，也不保证模型一定正确使用证据。模型可能忽略相关段落，偏向与之冲突的参数化关联，或从真实来源中做出没有依据的推断。

[第 11 章](./11-embeddings-and-retrieval.md)介绍 retrieval-augmented generation，以及外部文本进入 prompt 的路径。[第 12 章](./12-reasoning-tools-and-agents.md)说明模型生成拟议动作与外部系统执行动作之间的独立边界。

## 不确定性与校准

不确定性不等于校准（calibration）。从操作性定义看，如果一组预测被赋予信心水平 \(q\)，那么在具有代表性的这些预测中，约有 \(q\) 的比例正确，这组预测在信心水平 \(q\) 上就是校准的。例如，在被赋予 70% 信心的答案中，应当约有 70% 正确。因此，校准是要在大量案例上测量的性质，不是由一句自信表述就能确立的性质。

准确率与校准也不相同。模型可能平均准确率很高，却对许多错误答案都赋予 99% 信心；也可能准确率较低，但报告的概率更符合实际观察频率。校准会随领域、问题格式、prompt、decoding 设置和 post-training 而变化。

以下三个量不应混为一谈：

- **言语信心（verbal confidence）**是“可能”或“肯定”这样的措辞。它是生成文本，既可能反映表达风格，也可能反映不确定性；
- **Token 概率（token probability）**是模型为某个特定 next token 赋予的概率。它衡量表层 continuation 的可能性，并不直接等于完整主张为真的概率；
- **答案正确概率（answer-correctness probability）**是在已定义评判规则的任务上，对最终答案正确可能性的估计。标准语言模型回答不会自动提供这个量。

研究显示，模型有时可以估计自己是否知道某个答案，但这种能力无法完美迁移到所有任务和 prompt（[Language Models Mostly Know What They Know](https://arxiv.org/abs/2207.05221)）。因此，自报或引出的信心只是关于模型行为的证据，不是对答案的独立验证。

## 认知性弃答是一种习得行为

**认知性弃答（epistemic abstention）**是指模型因为无法用足够的知识或证据支持答案而放弃作答。“我不知道”和“提供的信息不足”这样的措辞是输出行为，并非从某个专门的不确定性寄存器中直接读出的结果。

模型倾向于作答而不是弃答，并非只有一个来源：next-token 目标、预训练数据中形如答案的模式、prompt 措辞和 post-training 偏好都可能产生影响。Karpathy 的 deep dive 强调了这个问题的一种表现：回答 demonstration 通常包含自信、完整的回答，却很少出现“我不知道”的样例（[Deep Dive, around 01:20:32](https://www.youtube.com/watch?v=7xTGNNLPyMI&t=4832s)）。这会强化形如答案的 completion，但只用 SFT 并不能完整解释幻觉。

Post-training 可以显式奖励模型在超出已展示知识边界的问题上弃答。这种学得的行为仍不完整：模型可能面对陌生的知识缺口却没有弃答，也可能在原本能够回答时弃答。因此，弃答是一种有用行为，却不能证明模型完美探测到了内部知识边界。

## 安全拒答与 Jailbreak

**安全拒答（safety refusal）**是指请求落入学得的不安全或不允许行为类别时，模型拒绝执行该请求。它不同于认知性弃答：模型可能完全理解一个请求，却出于安全原因拒答；一个无害问题也可能只因为答案未知而需要弃答。

安全拒答受 post-training 和 context 塑造，因此是概率性行为，不是硬性保证。**Jailbreak** 是试图诱导模型绕过这些学得的安全约束，例如通过角色扮演、假设语境或编码指令来重构请求。Karpathy 在 introduction 中用 jailbreak 例子说明 refusal behavior 可能受到 context 干扰（[Intro to LLMs, around 00:46:16](https://www.youtube.com/watch?v=zjkBMFhNj_g&t=2776s)）。

Jailbreak 与 prompt injection 有关，但并非同义词。Jailbreak 由“绕过行为约束”这一目标定义，可以直接来自用户。[Prompt injection](./08-prompting-and-in-context-learning.md#prompt-injection-是上下文混淆)则发生在不可信内容提供了类似指令的文本，并让模型以违背预期任务的方式改变行为；它可能针对安全约束，也可能只是重定向一个原本无害的任务。当注入内容试图绕过安全约束时，两者才会重叠。

因为拒答是一种习得行为，有关访问或外部动作的保证必须存在于模型之外。[第 12 章](./12-reasoning-tools-and-agents.md)介绍执行边界，详细的系统控制属于配套教材 [Agent Harness](../agent-harness-zh/README.md)。

## 模型自我报告不是权威元数据

“你是什么模型？”、“你的训练 cutoff 是什么时候？”或“你能浏览网页吗？”这些问题，仍然是在要求模型生成另一个 continuation。答案可能反映 post-training 样例、当前 prompt，或 application 提供的信息；它不是对部署配置的内省式读取。

自我报告可能正确，尤其是在 context 中已有准确 metadata 时，但这段生成文字本身不能确立其准确性。模型身份、发布信息和部署能力是模型 artifact 与外围系统的属性，不应从模型的文字中推断。

## 引用形幻觉

引用尤其有说服力，因为它的格式暗示背后存在证据。即使没有对应来源，模型也可能生成看似合理的标题、作者、期刊、法条编号、URL 或引文。它还可能引用真实存在但并不支持相关主张的来源，或把有效引用放到错误的句子后面。

以下三个问题彼此独立：

1. **来源存在性（source existence）：**被引用的来源是否存在？
2. **主张支持性（claim support）：**该来源是否真的支持对应主张？
3. **引用附着关系（citation attachment）：**引用的格式和位置能否明确指出它支持的主张？

一条格式精美的引用，单凭外观无法回答以上任何问题。[第 11 章](./11-embeddings-and-retrieval.md)介绍检索和来源追踪，[第 13 章](./13-evaluation-for-llm-behavior.md)介绍如何评估事实与引用的正确性。

## 模型失败与系统失败

引入外部证据或 observation 后，最终答案错误并不能自动证明内容是模型编造的。如果模型忠实总结了一条错误 observation，失败来自上游来源或系统，即使最终主张仍然是错的。如果 observation 正确，模型却与之矛盾或添加了没有依据的主张，那么这部分属于模型失败。两者也可能出现在同一个答案中。

这一概念区别很重要，因为 grounding 改变了模型收到的内容，并没有把模型和外围系统合并成同一个组件。诊断完整的证据、工具、权限和执行路径属于系统主题，由配套教材 [Agent Harness](../agent-harness-zh/README.md)展开。

## 要点

- 参数化知识是分布式且会犯错的，不是权威数据库。
- 流畅的假答案来自预测式训练、不完美数据、形如答案的 prompt 和学得的回答偏好。
- 幻觉包括回忆错误、知识过时、混合拼接、模仿性错误、错误前提顺从，以及对已提供证据的误用。
- 校准需要跨案例测量；言语信心、token 概率和答案正确概率是不同的量。
- 认知性弃答与安全拒答服务于不同目的；两者都是习得行为，而非绝不会失效的内部信号。
- Jailbreak 针对学得的行为约束；prompt injection 描述不可信指令改变预期任务。
- 模型自我报告和引用形文本都不是权威 metadata，也不能证明主张得到支持。
- 错误的系统输出可能来自模型错误、错误的外部 observation，或两者兼有。
